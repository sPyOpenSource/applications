Tracing a RISC-V Instruction Through the Simulator

src/jCPU/RiscV/IsaSim.java — the main loop

This lesson traces one RISC-V instruction through the full fetch→decode→execute→writeback cycle. By the end you should be able to open IsaSim.java and follow any instruction path without getting lost.

Prerequisites: Java, basic knowledge of RISC-V register names (x0–x31). No simulator knowledge needed.

The main loop: step()

The heart of the simulator is IsaSim.step() (line 66). Every tick of the simulation calls this method once. It does exactly four things in order:

// 1. FETCH — read the instruction word from memory at PC
int instr = code.read32(pc);

// 2. DECODE — extract the opcode (low 7 bits)
int opcode = instr & 0x7f;

// 3. EXECUTE — dispatch to the right handler
switch (opcode) {
    case LUI_MASK:       loadUpperImmediate(instr);      break;
    case JAL_MASK:       jumpAndLink(instr);             break;
    case BRANCH_MASK:    offsetPC = branchInstruction(instr); break;
    case OP_IMM_MASK:    immediateInstruction(instr);    break;
    case OP_MASK:        arithmeticInstruction(instr);   break;
    // ... 7 more cases
}

// 4. WRITEBACK — advance PC (unless a branch modified it)
if (!offsetPC) { pc += 4; }
offsetPC = false;
reg[0] = 0;          // x0 is always zero

That's the entire single-cycle model in ~90 lines. Every RISC-V instruction — whether it's ADD, LW, JAL, or ECALL — passes through this same switch statement.

Example: tracing an ADD instruction

Imagine memory at pc = 0x100 contains the 32-bit word 0x001100B3. Let's trace it.

1. Fetch

int instr = code.read32(0x100);
// instr = 0x001100B3

2. Decode

int opcode = instr & 0x7f;
// 0x001100B3 & 0x7f = 0x33

0x33 is OP_MASK — the RISC-V opcode for register-register arithmetic. The switch dispatches to arithmeticInstruction(instr).

3. Execute: arithmeticInstruction

Open IsaSim.java:516.

int rd  = (instr >> 7)  & 0x1F;  // bits 11-7:  destination register
int rs1 = (instr >> 15) & 0x1F;  // bits 19-15: source register 1
int rs2 = (instr >> 20) & 0x1F;  // bits 24-20: source register 2
int funct3 = (instr >> 12) & 0x7;
int funct7 = (instr >> 25);

For our instruction 0x001100B3:

FieldValueMeaning
opcode (bits 6-0)0x33OP (register-register ALU)
rd (bits 11-7)00001 = x1Write destination
funct3 (bits 14-12)000ADD / SUB / SLL / ...
rs1 (bits 19-15)00010 = x2First source
rs2 (bits 24-20)00011 = x3Second source
funct7 (bits 31-25)0000000ADD (not SUB)

The dispatch logic (line 583):

switch (funct3) {
case 0x0: // ADD or SUB
    if (funct7 == 0x00) {        // ADD
        reg[rd] = reg[rs1] + reg[rs2];  // x1 = x2 + x3
    } else {                     // SUB
        reg[rd] = reg[rs1] - reg[rs2];
    }
    break;

funct3 == 0 and funct7 == 0 → ADD. The result of x2 + x3 is written into x1.

4. Writeback

Back in step():

if (!offsetPC) { pc += 4; }  // pc was 0x100, now 0x104
offsetPC = false;
reg[0] = 0;  // hardware guarantee: x0 is always zero

Contrast: an I-type instruction (ADDI)

ADDI uses the same opcode dispatch OP_IMM_MASK → immediateInstruction. The difference: instead of reading rs2 from the register fields, it sign-extends the 12-bit immediate from bits 31-20:

int imm = (instr >> 20);
if ((imm >> 11) == 1) { imm |= 0xFFFFF000; }  // sign-extend

switch (funct3) {
case 0x0: // ADDI
    reg[rd] = reg[rs1] + imm;
    break;
...

Immediate instructions are the same pattern as register instructions — just with an encoded constant instead of a second register read.

The real loop: go()

The outer loop (line 57) is even simpler:

public void go(int limit) throws Exception {
    while (true) {
        RVInstruction ins = new RVInstruction(code.read16(pc));
        decode_riscv_binary(ins);
        step();
    }
}

It first runs the Decoder (inherited from Decoder.java) which pre-decodes the instruction into an RVInstruction struct, then calls step(). The step() acts as the execute phase, reading from the struct's already-decoded fields. The Decoder handles compressed (16-bit) instructions and floating-point, while step() handles the base RV32IM set.

Key insight: Once you know the step() switch, you know the entire simulator. Each case branch is a method that decodes fields from the instruction word and mutates reg[] and pc. Nothing else happens. No pipeline stages, no hazard detection, no cache — just fetch, decode, compute, write.
