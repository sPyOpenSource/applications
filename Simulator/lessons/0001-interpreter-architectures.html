📚 The Spectrum of Execution Models

Every language engine must transform source code into executable behavior. The spectrum runs from pure interpretation (slow, simple) to full compilation (fast, complex). Modern engines live in the middle, combining techniques.

🔍 Three Architectural Eras

Era 1: Tree-Walking Interpreters (1990s)

The simplest approach: parse source into an Abstract Syntax Tree (AST), then recursively walk the tree evaluating nodes.

// Simplified tree-walking evaluator
function evaluate(node, env) {
    switch (node.type) {
        case 'Number': return node.value;
        case 'Add':    return evaluate(node.left, env) + evaluate(node.right, env);
        case 'Var':    return env.get(node.name);
        case 'Assign': env.set(node.name, evaluate(node.value, env)); return;
        case 'Call':   return callFunction(evaluate(node.callee, env), 
                                           node.args.map(a => evaluate(a, env)));
    }
}

⚠️ Why Tree-Walking Failed at Scale

  • No caching: Same code re-parsed and re-walked every execution
  • No optimization: Can't specialize hot paths
  • Memory overhead: AST nodes carry metadata not needed at runtime
  • Stack overhead: Recursive calls for every expression

Era 2: Bytecode Virtual Machines (2000s)

Compile source once to a compact, portable bytecode. A fast loop interprets bytecode instructions.

Era 3: JIT Compilation (2010s+)

Modern engines start with bytecode interpretation, then compile hot paths to optimized machine code.

Aspect Tree-Walking Bytecode VM JIT Compilation
Startup Time Fastest Fast Slower (warmup)
Peak Performance Slow (10-100x slower) Moderate (2-10x slower) Near-native
Memory Low Low-Medium High (code cache)
Complexity Simple Moderate Very Complex
Portability Easy High (bytecode) Architecture-specific

💡 Why This Matters for You

"Understanding the engine pipeline transforms performance tuning from guesswork into engineering." — V8 Team Philosophy
  • Optimization clues: Engines optimize patterns (monomorphic calls, stable shapes). Knowing this guides code structure.
  • Debugging: Stack traces, deopt reasons, and GC pauses make sense when you know the pipeline.
  • Security: Type confusion, JIT spraying, and side-channels exist at compiler boundaries.
  • Tooling: DevTools, profilers, and tracers expose engine internals directly.

✅ Lesson 1 Complete — Key Takeaways

  1. Tree-walking is simple but doesn't scale — no caching, no optimization
  2. Bytecode VMs add a compilation step: portable, fast startup, moderate speed
  3. JIT compilation adds speculative optimization: near-native speed, complex
  4. Modern engines combine all three: parse → bytecode → interpret → profile → compile → deoptimize
  5. V8's pipeline (Ignition → TurboFan) is the canonical modern architecture
