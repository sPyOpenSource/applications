Special Function Registers

How the J51 simulator implements SFRs — the communication backbone between CPU and peripherals

src/j51/intel/MCS51Constants.java → MCS51.java → peripheral listeners

Motivation

The G128x64 graphics LCD, the Uart serial port, the LCD2x16 character display, and every port pin in the J51 simulator all talk to the CPU the same way: through Special Function Registers. Understanding SFRs is the key to adding any new peripheral — a VGA console, a keypad, an I²C bus — or debugging why an existing one doesn't respond.

What is an SFR?

The 8051 reserves addresses 0x80–0xFF in its direct-addressing space for Special Function Registers. These are not RAM — each SFR is a dedicated control/status register wired to a specific hardware unit:

AddressSymbolPurpose
0x80P0Port 0 latch
0x81SPStack pointer
0x82–0x83DPL, DPHData pointer (low/high)
0x88TCONTimer control
0x89TMODTimer mode
0x8A–0x8DTL0, TL1, TH0, TH1Timer values
0x98SCONSerial control
0x99SBUFSerial data buffer
0xA0P2Port 2 latch
0xA8IEInterrupt enable
0xB0P3Port 3 latch
0xD0PSWProgram status word
0xE0ACCAccumulator
0xF0BB register

These are the hardware-defined ones. User peripherals can add their own virtual SFRs at unused addresses — that's exactly what G128x64 does with ADDL=0xFD, ADDH=0xFE, DATA=0xFF.

Layer 1: Address constants

MCS51Constants.java is a plain interface with static final int constants for every standard SFR address. This is what peripherals import when they refer to SBUF or SCON or P0. Custom peripherals define their own constants (like ADDL = 0xFD).

Layer 2: VolatileMemory & the write listener chain

VolatileMemory (src/j51/device/VolatileMemory.java) manages an array of MemoryByte objects. Its write(address, newValue) method is the hot path — every SFR write flows through it:

// VolatileMemory.java:185
public void write(int address, int newValue) {
    MemoryByte b = memory[address];
    int oldValue = b.value;
    b.value = newValue;

    if (writeListener && b.mw != null) {         // any listeners?
        if (!b.writeBusy) {
            b.writeBusy = true;
            for (int i = b.mw.size(); --i >= 0; ) {
                b.mw.get(i).writeMemory(address, newValue, oldValue);
            }
            b.writeBusy = false;
        }
    }
}

Key details:

  • b.mw is a FastArray<MemoryWriteListener> — lazily created when the first listener registers
  • The writeBusy flag prevents recursive listener calls
  • writeListener can be globally disabled (used during reset to batch initialisation without triggering side-effects)
  • Listeners iterate in reverse order (--i >= 0) — so the last-registered listener fires first

Layer 3: SfrPage

SfrPage extends VolatileMemory with a fixed 256-byte size. Its constructor creates a SfrRegister for each address:

// SfrPage.java:22
public SfrPage(int page) {
    super("SFR", 256);
    this.page = page;
    for (int i = 0; i < 256; i++)
        setMemory(i, new SfrRegister(i));
    setPresent(0, 256);
}

The page concept (constructor parameter page) supports the 8051's SFR paging extension — some modern 8051 derivatives have multiple SFR pages switched via a bank-select register. The default is page 0.

Layer 4: MCS51 convenience API

Rather than calling sfrCurrent.write() directly, the CPU exposes a cleaner interface:

// MCS51.java:1273
public int sfr(int add) {
    return sfrCurrent.read(add);
}

// MCS51.java:1304
public void sfr(int add, int value) {
    sfrCurrent.write(add, value);
    // ... then check for interrupt conditions
}

And bit-level helpers that compile to the same sfr() calls:

sfrIsSet(addr, mask)   // → (sfr(addr) & mask) == mask
sfrSet(addr, mask)     // → sfr(addr, sfr(addr) | mask)
sfrReset(addr, mask)   // → sfr(addr, sfr(addr) & ~mask)

The peripheral doesn't talk to MemoryByte or VolatileMemory directly. It talks through adapters:

When a peripheral calls cpu.addSfrWriteListener(addr, this):

// MCS51.java:707
public void addSfrWriteListener(int sfr, SfrWriteListener listener) {
    addSfrMemoryWriteListener(sfr, new MemoryWriteListenerSfr(listener));
}

// The adapter is trivial — it just bridges interfaces:
// MemoryWriteListenerSfr (src/j51/intel/MemoryWriteListenerSfr.java)
public class MemoryWriteListenerSfr implements MemoryWriteListener {
    SfrWriteListener l;
    MemoryWriteListenerSfr(SfrWriteListener l) { this.l = l; }
    public void writeMemory(int address, int newValue, int oldValue) {
        l.sfrWrite(address, newValue);
    }
}

This adapter pattern separates the low-level MemoryWriteListener (which receives all memory writes including old value) from the high-level SfrWriteListener (which receives just the register and new value). Most peripherals only need the high-level interface.

Why the adapter?

The MemoryWriteListener interface is more general — it receives (address, newValue, oldValue) and could be used for non-SFR memory monitoring. The MemoryWriteListenerSfr adapter narrows this to the simpler sfrWrite(register, value) signature that most peripherals want. The same pattern exists for reads: MemoryReadListenerSfr → SfrReadListener.

Walkthrough: UART peripheral

Open src/j51/device/Uart.java. The UART registers for two SFR addresses and one interrupt:

// Uart.java:44
public void registerCpu(MCS51 cpu) {
    this.cpu = cpu;
    cpu.addSfrWriteListener(MCS51Constants.SBUF, this);  // 0x99 — data out
    cpu.addSfrReadListener(MCS51Constants.SBUF, this);   // 0x99 — data in
    cpu.addInterruptSource(MCS51Constants.IE, this, "UART0");
    cpu.addInterruptSource(MCS51Constants.SCON, this, "UART0");
    cpu.addResetListener(this);
}

When the 8051 program executes MOV SBUF, A (which writes to address 0x99), the call chain is:

  1. CPU executes the MOV instruction → calls sfr(0x99, value)
  2. sfr() calls sfrCurrent.write(0x99, value) (VolatileMemory.write)
  3. VolatileMemory updates the byte value, then iterates memory[0x99].mw
  4. MemoryWriteListenerSfr receives writeMemory(0x99, value, oldValue)
  5. Uart.sfrWrite(0x99, value) fires → calls sendChar(value) and sets the TI flag

Walkthrough: G128x64 graphics LCD

Open src/j51/test/x86.java. This peripheral uses three custom SFR addresses:

class G128x64 extends j51.device.lcd.GLcd
    implements MCS51Peripheral, SfrWriteListener, SfrReadListener {

    private final int ADDL = 0xFD;   // address low byte
    private final int ADDH = 0xFE;   // address high byte
    private final int DATA = 0xFF;   // data byte

    private int address = 0;          // current pixel position
    private MCS51 cpu;

    public void registerCpu(MCS51 cpu) {
        this.cpu = cpu;
        cpu.addSfrWriteListener(ADDL, this);
        cpu.addSfrWriteListener(ADDH, this);
        cpu.addSfrWriteListener(DATA, this);
        cpu.addSfrReadListener(DATA, this);
    }

    public void sfrWrite(int r, int v) {
        switch (r) {
            case ADDL: address = (address & 0xFF00) | (v & 0xFF); break;
            case ADDH: address = (address & 0x00FF) | (v << 8);  break;
            case DATA: setMemory(address, (byte)(v & 0xFF));       break;
        }
    }

    public int sfrRead(int r) {
        return getMemory(address) & 0xFF;  // read back from pixel RAM
    }
}

The 8051 program sends a byte to the LCD by writing three SFRs: MOV ADDL, #low(addr), MOV ADDH, #high(addr), MOV DATA, #byte. Each SFR write triggers the corresponding sfrWrite() callback.

The General Pattern

Every GUI-visible peripheral in J51 follows the same skeleton:

class MyPeripheral extends JPanel     // (or JComponent)
    implements MCS51Peripheral,        // required for addPeripheral()
               SfrWriteListener,       // ← handle inbound data
               SfrReadListener {       // ← provide outbound data (optional)

    private MCS51 cpu;

    public void registerCpu(MCS51 cpu) {
        this.cpu = cpu;
        cpu.addSfrWriteListener(ADDR1, this);
        cpu.addSfrWriteListener(ADDR2, this);
        // optional:
        cpu.addSfrReadListener(ADDR1, this);
        cpu.addResetListener(this);
        cpu.addUpdatableComponent(this);  // for periodic repaint
    }

    public void sfrWrite(int register, int value) {
        // react: update state, buffer data, trigger redraw
    }

    public int sfrRead(int register) {
        return someValue;  // return data to the CPU
    }
}

Then in the CPU subclass constructor:

addPeripheral(new MyPeripheral());

The addPeripheral() method calls registerCpu(this) automatically, so the peripheral is fully wired on construction.

Contrast: RISC-V vs 8051

The RISC-V simulator has no SFRs. Its peripherals connect through memory-mapped IO (a dedicated address range in the flat 32-bit address space) or through ECALL-based system calls. The J51 8051 simulator uses SFRs because the 8051 architecture has no concept of memory-mapped peripherals — all IO goes through the MOV instruction to the SFR address space 0x80–0xFF.

This makes the 8051 model tighter: every IO operation is an explicit write to a named register. The listener chain ensures that the timing and ordering of peripheral updates matches the real hardware cycle-by-cycle.
