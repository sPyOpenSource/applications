Bytecode model

ByteCode subclasses selected by opcode in newByteCode (ByteCode.java:125):

  • BCBranch — if/if_icmp/if_acmp, goto, jsr, ret
  • BCMultiBranch — tableswitch, lookupswitch
  • BCCPArgOp — anything reading the constant pool (new, getfield, invoke*, ldc, checkcast…)
  • BCWideOp — wide-form local-variable ops
  • plain ByteCode — everything else

Terminal ops (returns, athrow) get zero targets (linkTargets, ByteCode.java:200); every other op targets its fall-through successor plus branch targets.

The worklist algorithm

runChecks():
  stamp first BC with initialState.copy()      # signature-derived state
  srs.registerSrs(code)                        # find JSR/RET subroutines
  checkBC(firstBC); continueChecks()

continueChecks():                              # LIFO queue
  while queue not empty:
    bc = queue.popLast()
    bc.beforeState.executeNextBC()

executeNextBC():                               # JVMState.java:71
  tmp = this.copy()
  if nextBC is JSR/JSR_W:                      # subroutine call edge
      srs.transformState(tmp, nextBC); return
  for eh in nextBC.eHandlers:                  # exception edges
      eh.simulateException(this)               #   → exceptionThrown():
                                                #     clear stack, push eName, nextBC=handler
  targetStates = tmp.doExecuteNextBC()         # analysis-specific simulation
  for each successor s with incoming state st:
      if s.beforeState == null: s.beforeState = st; checkBC(s)
      elif s.beforeState.merge(st) changed:    # dataflow join
          checkBC(s)                           # re-analyze
  # queue drains ⇔ fixed point reached

Merge rules (the join)

  • Stack depth must match across paths — else VerifyException "Stacks of different size" (JVMOPStack.java:124).
  • Object types merge to first common superclass (via ClassTree), or T_OBJECT if none (TCObjectTypes.java:239).
  • null merges into any object type (TCObjectTypes.java:232).
  • Primitive types must be identical, else exception.
  • Merge returns true if anything changed → successor re-queued. This loop is the fixed-point iteration.

JSR/RET subroutines

  • Found by Subroutines.registerSrs (pre-pass over the CFG).
  • Each subroutine verified by its own SubroutineVerifier worklist; RET bytecodes merge their states into SubroutineData.finalState (SubroutineVerifier.java:79).
  • Return addresses are abstract values — TCRAType — tagged with the subroutine start address (TCState.java:42).
  • The calling JSR edge merges finalState into every RET target (Subroutines.transformState).
  • This is the pre-Java-6 (pre-StackMapTable) verifier style; modern JVMs ban JSR/RET.

Glossary

beforeState
Abstract JVM state flowing into a bytecode; the per-node lattice value of the dataflow analysis (ByteCode.java:13).
checkQueue / worklist
LIFO set of bytecodes awaiting (re-)analysis; LIFO order prevents double subroutine analysis (MethodVerifier.java:115).
merge / join
Combining abstract states at a CFG merge point; returns true on change to drive re-analysis (JVMState.java:169).
fixed point
Queue empty ⇔ every state stable ⇔ verification complete.
abstract interpretation
Executing the method on abstract values (types, nullness, cost) instead of concrete ones.
JSR subroutine
Legacy code-sharing block via jsr/ret; verified separately because return addresses make locals polymorphic.
exception edge
State transition to a handler: stack cleared, exception type pushed (TCState.java:25).
