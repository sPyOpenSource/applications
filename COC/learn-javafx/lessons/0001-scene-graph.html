The Scene Graph: How a COC Screen Is Built

🎯 Win of the day: read any screen file in src/view/ and draw its scene graph from memory.

Before you can redesign a screen, you must be able to see it — not as pixels, but as a tree. That tree is the scene graph. In this lesson we'll build the mental model and trace it through the real LogIn.java.

1. The three-layer window stack

Every JavaFX screen is three nested layers. Outer to inner:

Stage        the OS window (title bar, size, position)
└── Scene    the canvas inside it (one root node + size + stylesheets)
    └── root + descendants   ← this tree is the SCENE GRAPH
  • Stage — the window itself. stage.setTitle("Log in"), stage.setScene(scene), stage.show().
  • Scene — holds exactly one root node, plus a size and the stylesheets.
  • Scene graph — the tree of nodes hanging off that root.

2. Every item is a node — branch or leaf

Everything visible is a Node. Two flavours:

Branch (Parent)Leaf
Has children. Layout panes (VBox, BorderPane, AnchorPane…), Group, controls. No children. ImageView, Text, Rectangle, MediaView, shapes.

A node has at most one parent, and the graph must have no cycles. (OpenJFX — Node)

3. Trace it in your code

Open src/view/LogIn.java. The start method builds the top layers, then delegates the centre to a helper:

// LogIn.start(Stage stage)
BorderPane root = new BorderPane();              // the ROOT (a branch)
root.setBackground(...);
root.setCenter(vBoxFields(stage));               // attach a branch into "center"
Scene scene = new Scene(root, 400, 300);         // Scene wraps the root
scene.getStylesheets().add("style.css");         // CSS hook
stage.setScene(scene);                           // Stage wraps the Scene
stage.show();
root.getChildren().add(new MediaView(...));      // leaf added after show

And vBoxFields() returns a VBox — a branch — holding a title, two fields, and an HBox of buttons. Putting it together, the scene graph is:

Stage "Log in"
└── Scene (400×300, +style.css)
    └── BorderPane                    ← root (branch)
        ├── VBox   [set as center]    ← branch
        │   ├── Text "Log In"         leaf
        │   ├── TextField (username)  leaf
        │   ├── TextField (password)  leaf
        │   └── HBox                  ← branch
        │       ├── Button "Sign Up"  leaf
        │       └── Button "Log In"   leaf
        └── MediaView                 leaf (added after show)
Two layout styles coexist. LogIn uses a VBox with spacing/alignment (auto layout). PlayerPanel and Battle instead place nodes with setX/setY (absolute). For the redesign you'll favour auto layout — but you must first recognise which style each screen uses.
The quirk you'll fix later. Each screen here is its own Application subclass, opened with new SignUp(players).start(new Stage()). A normal app has one Application launched by launch(). This is the structural smell at the heart of the GUI. Lesson 1 only asks you to see it.

🛠 Hands-on (5 min)

  1. Open src/view/LogIn.java and match each line in start() + vBoxFields() to the tree above.
  2. Make one reversible change in vBoxFields so you can see the VBox's bounds: 
    vBox.setStyle("-fx-background-color: rgba(21,101,192,0.35);" +
              "-fx-border-color: #1565c0;");
  3. Rebuild and run. Notice the VBox now visibly fills the BorderPane's centre region only.
  4. Remove the line. Can't build/run yet? Do the trace on paper — we'll set up a run config in a later lesson.

Summary

  • A screen = Stage → Scene → scene graph.
  • Every item is a Node: branch (Parent, has children) or leaf (no children).
  • You attach children via getChildren() or layout-specific setters like setCenter().
  • LogIn mixes auto layout (VBox) with the project's one-Application-per-screen pattern.
