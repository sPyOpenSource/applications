Lesson 0003: HTTP Response Structure

Mission: HTTP Servers | Lesson: 0003

Learning Goal

Learn how HTTP responses are constructed and sent back to clients.

Tangible Win: Understand how constructHeader() works and why Content-Length and Content-Type matter.

Anatomy of an HTTP Response

A typical HTTP response looks like this:

HTTP/1.0 200 OK
Content-Length: 123
Content-Type: text/html

<html>...body content...</html>

Parts:

  1. Status Line - HTTP/VERSION STATUS_CODE REASON_PHRASE (HTTP/1.0 200 OK)
  2. Headers - Metadata about the response (Content-Length, Content-Type, etc.)
  3. Empty Line - Separates headers from body
  4. Body - The actual content being sent

Building Responses in the Code

In TCPWebWorker, responses are built via constructHeader() methods:

static public String constructHeader(String fileName, int fileLength) {
    String fileType;
    fileType = fileName.substring(fileName.lastIndexOf(".") + 1, fileName.length());
    fileType = getProperty_MimeTypes(fileType);
    return constructHeader(fileName, fileType, fileLength);
}

static public String constructHeader(String fileName, String fileType, int fileLength) {
    return  "HTTP/1.0 200 OK\n"
        + "Content-Length: " + fileLength + "\nContent-Type: " + fileType + "\n\n";
}

static public String constructErrorHeader() {
    return  "HTTP/1.0 404 File not found\n" + "Allow: GET\n" + "MIME-Version: 1.0\n"
        + "Server : JX HTTP Server\n" + "\n\n <H1>404 File not Found</H1>\n";
}

Why Content-Length is Critical

Content-Length tells the client how many bytes of body follow the headers. This is essential because:

  • The connection might be persistent (keep-alive) in HTTP/1.1
  • Without it, client can't know when response ends
  • It enables proper parsing and prevents reading extra data

In this implementation, they compute data.length and put it in the header.

MIME Types

The code does a simple MIME type mapping:

static String getProperty_MimeTypes(String fileType) {
    if (fileType.equals("html")) return "text/html";
    if (fileType.equals("htm")) return "text/html";
    return fileType; 
}

For other extensions like "txt", "jpg", "css", it just returns the extension as-is. Real servers have comprehensive MIME type tables. But for this simple case, it works if the extension happens to be the MIME type - or if clients are lenient.

Proper MIME types tell the browser how to interpret the content (render as HTML, display as image, download as binary, etc.)

Status Codes

This server returns:

  • 200 OK - Request succeeded, content follows
  • 404 File not found - When readFile() throws an exception

Status codes are grouped: 2xx (success), 3xx (redirection), 4xx (client error), 5xx (server error). Even this minimal set covers common cases.

Sending the Response

ostream.write(constructHeader(file, data.length).getBytes());
ostream.write(data);
ostream.flush();
sock.close();

Notice: header and body are written as separate byte arrays. The header is constructed as a String then converted to bytes. The body comes from the file content (also bytes). After sending, the connection is closed - this is HTTP/1.0 style behavior (connection: close by default).
