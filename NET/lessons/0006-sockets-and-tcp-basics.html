What is a Socket?

A socket is an endpoint for network communication. In Java (and most systems), you have:

  • ServerSocket - Listens for incoming connections on a port
  • Socket - Represents a connection to a client (or to a server when connecting out)

Sockets provide bidirectional byte streams - you can read from and write to them.

Socket Lifecycle in the Server

From WebServer.java:

// 1. Create ServerSocket bound to port
ServerSocket ssock = new ServerSocket(port);

// 2. Accept loop - blocks until client connects
while (true) {
    // accept() returns a new Socket for this client
    final Socket sock = ssock.accept();
    // 3. Hand off to worker for processing
    ...
}

From TCPWebWorker:

// 4. Get I/O streams from the connected socket
OutputStream ostream = sock.getOutputStream();
DataInputStream requestStream = new DataInputStream(sock.getInputStream());

// 5. Read request, write response
// ... parse reads from requestStream ...
// ... write headers/body to ostream ...

// 6. Close the connection
ostream.flush();
sock.close();

Key Methods Explained

MethodPurpose
new ServerSocket(port)Binds to the specified port and starts listening
accept()Blocks waiting for client. Returns a Socket when connection established
getInputStream()Read bytes from client
getOutputStream()Write bytes to client
close()Closes the socket/connection

TCP vs HTTP

It's important to distinguish the layers:

  • TCP (Transport) - Reliable, ordered byte stream. Handles packet loss, retransmission, flow control. Connection-oriented.
  • HTTP (Application) - Runs on top of TCP. Defines message format, semantics, methods, status codes.

The server is using TCP sockets as the transport; HTTP is the protocol written onto those streams.

Looking at a Simpler TCP Example

For contrast, look at TCPWorker.java - it just echoes chars until it sees 'X':

InputStream ips = sock.getInputStream();
for (char c=0; true; c=(char)ips.read()) {
    Debug.out.println("received: "+c);
    if (c == 'X') {
        DomainManager domainManager = (DomainManager) naming.lookup("DomainManager");
        domainManager.terminateCaller();
    }
}

This is even simpler - raw byte stream reading. The HTTP worker does structured parsing on top of the same raw stream.

Blocking I/O

All these socket operations are blocking:

  • accept() blocks until connection arrives
  • readLine() / read() block until data arrives
  • write() may block if buffer is full

This is why each connection needs its own worker (thread or domain) - otherwise the server would block on one connection and not accept others.
