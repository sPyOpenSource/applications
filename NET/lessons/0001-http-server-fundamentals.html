Learning Goal

By the end of this lesson, you will understand what an HTTP server does, its core responsibilities, and see how the JX implementation maps to these concepts.

Tangible Win: Be able to trace the flow of an HTTP request through WebServer.java and explain each step.

What is an HTTP Server?

An HTTP server (web server) listens for incoming TCP connections, reads HTTP requests, and sends back HTTP responses. At its most basic, it must:

  1. Listen - Bind to a port (typically 80 for HTTP) and accept connections
  2. Parse - Read and interpret HTTP request messages
  3. Route/Process - Determine what content to serve based on the request
  4. Respond - Send a properly formatted HTTP response
  5. Close - Clean up the connection

Looking at the JX Implementation

Our codebase has a simple HTTP server. Let's examine the key files.

WebServer.java - The Server Loop

// Key parts from WebServer.java
ServerSocket ssock = new ServerSocket(port);
while (true) {
    final Socket sock = ssock.accept();
    if (opt_threads)
        startWorkerThread(sock);
    else
        startWorkerDomain(sock);
}

This shows the classic accept loop: block until a connection arrives, then hand it off to a worker.

TCPWebWorker.java - Handling Requests

// Parse the request
String file = parse(requestStream);
// ... determine response based on file
byte[] data = index.getBytes();
ostream.write(constructHeader(file, data.length).getBytes());
ostream.write(data);
ostream.flush();
sock.close();

The worker reads the request, parses out the requested file, builds a response with headers + body, then closes the connection.

Try to Trace Through

Take a moment to mentally trace what happens when a browser requests http://localhost/index.html:

  1. Browser opens TCP connection to port 80
  2. ssock.accept() returns with the socket
  3. Worker (thread or domain) is started
  4. parse() reads HTTP request lines, extracts "index.html" (or "index.html" from "/")
  5. constructHeader() builds "HTTP/1.0 200 OK..." with Content-Type and Content-Length
  6. Both header and body bytes are written to socket
  7. Connection is closed

Key Concepts to Remember

  • TCP is the transport - HTTP runs on top of TCP. Sockets give you a byte stream.
  • HTTP is text-based (for 1.x) - Requests and responses are readable strings with headers followed by body.
  • Stateless by default - Each request is independent; no built-in session state.
  • Concurrency matters - This implementation supports both threads and JX domains. Different models, same protocol.
