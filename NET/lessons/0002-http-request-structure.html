Lesson 0002: HTTP Request Structure

Mission: HTTP Servers | Lesson: 0002

Learning Goal

Understand how HTTP requests are formatted and how the JX server parses them.

Tangible Win: Be able to identify the parts of an HTTP request and explain how TCPWebWorker.parse() extracts the filename.

Anatomy of an HTTP Request

A typical HTTP/1.1 GET request looks like this:

GET /index.html HTTP/1.1
Host: localhost:80
User-Agent: curl/8.0.1
Accept: */*

Key parts:

  1. Request Line - METHOD URI HTTP/VERSION (e.g., GET /index.html HTTP/1.1)
  2. Headers - Key-value pairs, one per line (Host, User-Agent, Accept...)
  3. Empty Line - CRLF that separates headers from body
  4. Body - Optional data (used by POST, PUT etc.)

How TCPWebWorker Parses Requests

Looking at the parse() method in TCPWebWorker.java:

while (! (line = fromClient.readLine()).equals("")) {
    StringTokenizer tokenizer = new StringTokenizer(line, " ");
    String tok = tokenizer.nextToken();
    switch (tok) {
        case "GET":
            method = METHOD_GET;
            fileName = tokenizer.nextToken(); // gets the URI
            if (fileName.endsWith("/")) {
                fileName = fileName + getProperty_DefaultFile();
            } else {
                fileName = fileName.substring(1); // strip leading /
            }
            break;
        case "POST":
            ...
        case "Content-length:":
            contentsLength = Integer.parseInt(tokenizer.nextToken());
            break;
        // ...
    }
}

Observations:

  • It reads lines until it hits an empty line ("")
  • For GET, it takes the second token as the URI/path
  • If URI ends with /, it appends index.html (default file)
  • Otherwise it strips the leading / to get the filename
  • It also captures Content-length if present

For request GET / HTTP/1.1, it becomes index.html.

Limitations of This Parser

The implementation is intentionally simple. Notice what's missing or simplified:

  • No handling of HTTP/1.0 vs HTTP/1.1 differences (keeps-alive, etc.)
  • Doesn't parse query strings (/file?param=value) - would treat the whole thing as filename
  • Limited header handling (only looks for Content-length:)
  • No support for other methods beyond GET/POST detection
  • Case-sensitive in places? Header names can vary in case per spec

This is fine for learning - it demonstrates the core idea clearly.
