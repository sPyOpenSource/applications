WebSocket Handshake Quick Reference

Client Request (Upgrade)

GET /ws HTTP/1.1
Host: example.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: base64(random-16-bytes)
Sec-WebSocket-Version: 13
[optional headers: Sec-WebSocket-Protocol, Sec-WebSocket-Extensions]

Server Response (101 Switching Protocols)

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: SHA1(Sec-WebSocket-Key + "258EAFA5-E914-47DA-95CA-C5AB0DC85B11") base64 encoded

Computing Sec-WebSocket-Accept (Conceptual)

  1. Take the client's Sec-WebSocket-Key value
  2. Concatenate with magic string: 258EAFA5-E914-47DA-95CA-C5AB0DC85B11
  3. Compute SHA-1 hash of the result
  4. Base64 encode the hash

After Handshake

  • Connection switches from HTTP to WebSocket protocol
  • Data is exchanged as frames (binary format), not HTTP messages
  • Each frame has opcode indicating text/binary/close/ping/pong
  • Masked frames from client to server (required); server frames unmasked

Codebase Notes

  • TCPWebWorker.parse() detects Sec-WebSocket-Key header (line ~142)
  • But doesn't act on it - no 101 response, no frame handling
  • To implement, need to change response logic when upgrade requested
