The Congruence of Squares

Lesson 1 · 15 min · Foundation for both QS and ECM

Every algorithm in this codebase — the Quadratic Sieve in com/gazman/factor/, the Elliptic Curve Method in ecm/ — is trying to find the same thing:

x2 ≡ y2  (mod n)   with  x ≢ ±y  (mod n)

This is called a congruence of squares, and it gives us a factor of n directly.

The Algebra

If x2 ≡ y2 (mod n), then the integer (x − y)(x + y) is divisible by n. If we also know x ≢ ±y (mod n), then n divides the product but not either factor individually — so gcd(x − y, n) must be a nontrivial divisor.

Key fact. Reducing factoring to finding a congruence of squares is not just a trick — it's an equivalence. Computing square roots modulo a composite number is probabilistic polynomial-time equivalent to factoring that number. [source]

Worked Example

Let's factor n = 1649 — the canonical classroom example from Pomerance's original QS paper.

First, pick numbers near ⌈√1649⌉ = 41:

a = 41:  412 = 1681 ≡ 32  (mod 1649)
a = 42:  422 = 1764 ≡ 115  (mod 1649)
a = 43:  432 = 1849 ≡ 200  (mod 1649)

None of the residues 32, 115, 200 are perfect squares. But look at their factorizations:

32 = 25    115 = 5 · 23    200 = 23 · 52

The product of 32 and 200 has only even exponents:

32 · 200 = 6400 = 28 · 52 = (24 · 5)2 = 802

So we have:

(41 · 43)2 ≡ 32 · 200 ≡ 802  (mod 1649)
17632 ≡ 802  (mod 1649)
x = 1763 mod 1649 = 114, y = 80

Check: 114 ≠ ±80 (mod 1649). So we compute:

gcd(114 − 80, 1649) = gcd(34, 1649) = 17

And 1649 = 17 × 97. Done.

Why this works. The key insight is that we didn't need any one residue to be a square — we needed a product of residues to be a square. That's much easier to find, and it's the engine behind every modern factoring algorithm.

The General Framework

The search for a congruence of squares splits into four steps:

  1. Build a factor base — a set of small primes B = {p₁, …, pk}.
  2. Collect relations — find values ai such that g(ai) = ai² − n factors completely over B (is B-smooth).
  3. Find a dependency — the exponent vectors of g(ai) modulo 2 form a matrix over 𝔽₂. Gaussian elimination finds a subset whose sum is the zero vector.
  4. Extract the factor — multiply the corresponding ai to get x, multiply the g(ai) to get y², compute gcd(x − y, n).

Step 3 is the crucial insight: once you have k + 1 relations (more rows than columns), a linear dependency is guaranteed by linear algebra over 𝔽₂.

Map to the Code

Let's see each step in the QuadraticSieve implementation:

Step 1: Factor base

275–288 buildPrimeBase(B_SMOOTH, N) collects the first B_SMOOTH = 5000 primes where N is a quadratic residue. The check is the Legendre symbol: N(p−1)/2 ≡ 1 (mod p) (line 17 of MathUtils.java).

Step 2: Sieving

146–208 sieve() evaluates g(x) = (root + position)² − N for a range of positions. Instead of dividing each value by each prime, it accumulates log(p) at every position divisible by p (tracked by the Wheel class). If the accumulated log approaches the true log of g(x), the value is likely B-smooth.

Step 3: Linear algebra

210–230 tryToSolve() passes the exponent vectors to BitMatrix.solve(), which performs Gaussian elimination over 𝔽₂ (the BitSet rows represent exponent vectors mod 2). Any row that becomes all-zero corresponds to a dependency.

Step 4: Extract factor

236–273 testSolution() multiplies the ai values (mod N) to get x, multiplies and square-roots the yi values to get y, then returns gcd(x + y, N).

Why This Matters for ECM

ECM pursues the same goal — a congruence of squares — but through a completely different mechanism. Instead of sieving for smooth numbers, Lenstra's method uses elliptic curves over ℤn. The group law on the curve provides a structure where "failure" of a computation (inversion modulo p but not modulo n) leaks a factor. Both algorithms converge on the same algebraic fact: x² ≡ y² (mod n) → gcd(x − y, n) gives a factor.

Retrieval Practice

Q1. You find x² ≡ y² (mod n) where x ≡ 3, y ≡ 10, and n = 91. What is the factor you extract?

Compute gcd(3 − 10, 91) = gcd(−7, 91) = 7. Check: 91 = 7 × 13.
Since 3 ≢ ±10 (mod 91), this is nontrivial.

Q2. You have collected 7 relations over a factor base of 5 primes. How are you guaranteed that a subset product is a square?

The exponent vectors are 5-dimensional over 𝔽₂. With 7 vectors in a 5-dimensional space, there must be a linear dependency. The sum of any dependent subset has even exponents in every prime — a perfect square.

Q3. True or false: the QS factor base should include every small prime up to some bound.

False. Only primes where n is a quadratic residue modulo p are included. If (n/p) = −1, then g(x) mod p is never 0 and the prime never helps — it only adds overhead. See the Legendre check in buildPrimeBase() at line 281.
